# Contributing

Thank you for contributing!

## Before making changes
1. Check open issues and pull requests for related work.
2. For significant changes, open an issue to discuss the proposal first.
3. Do not commit passwords, tokens, API keys, personal data, or other secrets.

## Workflow
1. Create a descriptive branch from `main`, such as `docs/update-guidelines`.
2. Make a focused change and write a clear commit message.
3. Test your changes and review your diff before pushing.
4. Open a pull request describing what changed, why, and how it was tested.
5. Respond constructively to review feedback and resolve conversations when addressed.

## Pull requests
- Keep one logical change per pull request where practical.
- Include screenshots for significant visual or documentation changes when helpful.
- Link relevant issues.
- Confirm that no secrets or unrelated files are included.

Maintainers review changes for correctness, clarity, security, and project fit before merging.
